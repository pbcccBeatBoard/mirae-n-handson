검증 대상: $ARGUMENTS

위 인자가 비어 있으면 `git diff upstream/main...HEAD` 를 대상으로 삼는다.

이 Skill 은 리뷰 세션 역할이다. 만든 세션의 설명이 아니라 변경분(diff)만 보고 판정한다. 참조하는 파일 경로는 모두 Skill 폴더가 아니라 **저장소 루트** 기준이다.

## 절차

1. **요청 범위 확인.** 무엇을 요청한 변경인지 한 문장으로 받는다. 인자나 대화에 요청 범위가 없으면 **판정하지 말고 먼저 사용자에게 질문**한다. 답을 받기 전에는 2번 이후로 넘어가지 않는다.
2. **변경 파일 목록과 diff 읽기.** `git diff --stat <범위>` 로 목록을 먼저 보고, 파일마다 diff 를 읽는다. patch 파일이면 `git apply --stat` 으로 목록을 뽑는다. 아직 커밋하지 않은 변경(unstaged · untracked)이 대상이면 `git status` 로 함께 확인한다.
3. **체크리스트 대조 (reviewer Sub-agent 에 위임).** 직접 대조하지 않고 `reviewer` Sub-agent 에 맡긴다. 1번에서 받은 비교 범위(diff 범위 · 대상 폴더)와 요청 범위를 가공하지 않고 그대로 넘긴다. reviewer 는 저장소 루트의 `templates/approval-checklist.md` 를 읽고, 그 안의 항목마다 충족 · 미충족 · 확인 필요 중 하나로 표시해 보고한다. 심각도(치명 / 경고 / 제안) 정의도 그 파일을 따른다. 컨벤션은 `convention-check` Skill 이 있으면 그 결과를 쓴다. 판정 흐름의 배경은 저장소 루트의 `templates/verification-loop.md` 에 있다.
4. **테스트 실행 (tester Sub-agent 에 위임).** 직접 실행하지 않고 `tester` Sub-agent 에 맡긴다. 3번과 같은 비교 범위와 요청 범위를 넘기고, 새 로직에 테스트가 없으면 테스트 파일을 추가하게 한 뒤 실행 결과(통과 · 실패 수, 실패한 테스트 이름, 추가한 테스트 파일 목록)를 돌려받는다. 실행 대상은 변경된 폴더의 테스트만이다.
   - `modern/api` 가 바뀌었으면 `cd modern/api && ./gradlew test`
   - `modern/web` 이 바뀌었으면 `cd modern/web && npm test`
   - 이관 코드(modern 쪽 API 가 레거시 동작을 대체하는 변경)는 `characterization` 에서 두 가지를 모두 실행한다.
     - `cd characterization && npm test` (레거시 대상)
     - `cd characterization && TARGET_BASE_URL=http://localhost:8080 npm test` (새 API 대상)
   - 서버 · DB 가 꺼져 있거나 의존성이 없어 실행할 수 없으면 그 사실을 적고, 사람에게 기동을 요청한다. 실행하지 못한 상태에서 테스트 기준을 충족으로 표시하지 않는다.
5. **승인 기준 판정.** reviewer 와 tester 두 보고를 받은 뒤 **메인 세션이** 네 기준(테스트 통과 / 치명 이슈 0건 / 요청 범위 이탈 없음 / 컨벤션 준수)을 하나씩 판정한다. 하나라도 미충족이면 반려다. 이슈가 0건이면 경고 · 제안 수준까지 한 번 더 훑은 뒤 결과를 낸다.
   - 두 보고가 엇갈리면(예: reviewer 는 충족, tester 는 실패) 임의로 한쪽을 고르지 않고, 엇갈린 지점을 양쪽 보고 그대로 적은 뒤 사람에게 묻는다.
6. **Sub-agent 가 없는 환경.** `reviewer` 또는 `tester` Sub-agent 가 없으면 기존 방식대로 메인 세션이 3 · 4번을 직접 수행한다.

## 출력 형식

````
판정: 승인 | 반려

| 기준 | 결과 | 근거 |
|---|---|---|
| 테스트 통과 | 충족 / 미충족 | 실행 명령과 통과 · 실패 수 |
| 치명 이슈 0건 | 충족 / 미충족 | 치명 이슈 번호 |
| 요청 범위 이탈 없음 | 충족 / 미충족 | 요청 문장 vs 변경 파일 목록 |
| 컨벤션 준수 | 충족 / 미충족 | 위반 항목 번호 |

이슈 목록
| # | 심각도 | 파일:줄번호 | 근거 | 수정 방향 |
|---|---|---|---|---|

확인 필요
- (근거 줄번호를 댈 수 없는 지적)
````

- 이슈 한 건은 `심각도(치명 / 경고 / 제안) · 파일:줄번호 · 근거 · 수정 방향` 순서로 네 항목을 모두 채운다.
- 근거 줄번호를 댈 수 없는 지적은 이슈로 올리지 않고 "확인 필요"에 따로 적는다.

## 사용량 절약

- 테스트 출력은 **통과 / 실패 수와 실패한 테스트 이름만** 남긴다. 전체 로그를 대화에 싣지 않는다.
- diff 는 파일마다 필요한 부분만 읽고, 판정에 쓰지 않은 내용을 길게 옮겨 적지 않는다.

## 하지 말 것

- **코드를 수정하지 않는다(tester 가 추가하는 테스트 파일은 예외).** 보고만 한다. 고치기 시작하면 만든 쪽이 된다.
- 근거 줄번호를 댈 수 없는 지적은 이슈로 올리지 않고 "확인 필요"로 남긴다.
- 테스트를 실행하지 않고 통과했다고 쓰지 않는다.
- 요청 범위를 모르는 상태에서 "요청 범위 이탈 없음"을 충족으로 표시하지 않는다.
- 체크리스트 항목을 이 파일에 복사하지 않는다. 항상 저장소 루트의 `templates/approval-checklist.md` 를 읽어서 쓴다.
