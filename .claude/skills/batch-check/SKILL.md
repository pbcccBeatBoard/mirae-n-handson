# 배치 점검

`$ARGUMENTS` 로 받은 폴더의 일자별 `*.log` 와, 그 폴더의 상위 폴더에 있는
`datamart-counts.csv` 를 점검한다. 인자가 없으면 `pipeline-samples/batch-logs` 를 쓴다.
로그 파일명 날짜는 `date=` 값이고 실제 기록 시각은 다음 날 새벽이다.

## 점검 기준

1. **실행 여부** — 다른 날 매일 돌던 job 이 그날 로그에 없거나, START 만 있고 종료(SUCCESS/FAIL) 기록이 없으면 이상
2. **중복 실행** — 같은 날 같은 job 의 SUCCESS 가 두 번 이상이면 이상
3. **적재 건수** — 직전 7일 평균에서 30% 넘게 벗어나면 이상. 0건은 무조건 이상
4. **지연** — 소요 시간(elapsed)이 그 job 의 평소 중앙값의 2배를 넘으면 이상

## 규칙

- 로그를 통째로 읽지 않는다. `grep` · `awk` · `wc` 로 필요한 줄만 뽑는다.
  (예: `grep -nE 'status=(START|SUCCESS|FAIL)'`, `grep -nvE ' INFO '`)
- 평균 · 중앙값 · 편차율은 암산하지 않고 `awk` 등 명령으로 계산한다.
- 근거는 이상마다 붙인다. 로그는 `파일명:줄번호`, 건수는 CSV 의 해당 행(행 번호와 값)이다.
- 로그에 없는 원인은 추측하지 않는다. 원인은 "확인 필요"로 남기고 무엇을 더 봐야 하는지만 적는다.
  로그 note 에 적힌 내용은 사실로 인용하되 "확정 원인인지는 확인 필요"로 구분한다.
- 점검 대상(로그 · CSV · 레거시 · 샘플)은 수정하지 않는다. DB 도 조회하지 않는다.
- 이상 판정이 아닌 반복 WARN 은 "참고"에만 적는다.

## 리포트

1. 먼저 이상 목록을 `날짜 / job / 점검 항목 / 근거` 표로 사용자에게 보여 준다.
2. 이상이 **한 건도 없으면 파일을 만들지 않고** "이상 없음" 한 줄만 답한다.
3. 이상이 있으면 `docs/batch-check/report.md` 에 저장한다. 형식:
   - 맨 위 요약 한 줄: 점검 기간, 이상 건수
   - 이상 목록 표: 날짜 / job / 점검 항목 / 근거 / 영향 추정 / 다음 확인 사항
     (영향 추정은 로그 · CSV 로 확인되는 사실만, 나머지는 "미확인")
   - 참고 (이상은 아니지만 알아둘 점)
   - 맨 아래 "이상 없음으로 판정한 날짜" 목록
4. 같은 사건이 두 기준에 걸리면 행은 나누되 같은 사건이라고 명시한다.
5. 저장 후 건수 합계를 요약 한 줄과 대조한다. 커밋은 하지 않는다(사용자 확인 후).
